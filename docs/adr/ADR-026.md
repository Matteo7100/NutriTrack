# ADR-026 — Provisioning account e sessioni
Stato: adottata nel completamento autorizzato del 30 ottobre 2026; precisa ADR-024.

## Decisione
Account predisposti tramite seed/CLI, ruoli assegnati dal sistema; niente registrazione pubblica o attore Admin aggiunti. Password salvate con scrypt e salt casuale, confronto sicuro. Sessioni server persistenti con ID casuale, scadenza di 8 ore, cookie HttpOnly e SameSite Strict; Secure nel contesto HTTPS operativo. Le mutazioni autenticate richiedono token CSRF separato dall'ID di sessione.

## Motivazione
Realizzare FR-01/02 senza un provider cloud, mantenendo identità fuori dai parametri controllati dal client. La predisposizione dei tre utenti dimostrativi serve alla prova, non è una nuova funzionalità di prodotto.

## Conseguenze
Login online; al sync sessione scaduta conserva la coda e richiede nuovo login. Nessuna password persistita nel browser. Recupero password, email e registrazione non sono aggiunti allo scope. Le credenziali demo sono dichiarate nel runbook e non vanno presentate come credenziali operative. Non si rivendica una certificazione di sicurezza o conformità normativa.
