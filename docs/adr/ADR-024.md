# ADR-024 — Auth, adapter di persistenza e test
Stato: Scelta tecnica adottata nel mandato di proseguire, 2026-10-05.

## Decisione
Email/password con sessione server e cookie HttpOnly, store persistente nel PostgreSQL posseduto da Identity. Hashing con libreria consolidata, protezione CSRF, revoca e rinnovo sessione; dettagli e dipendenze verificati prima dell'auth reale. Nessun provider cloud richiesto.
Prisma implementa repository privati; tipi generati non trapelano nei contratti. Migrazioni SQL per vincoli non rappresentabili dall'ORM.
Jest backend e Vitest frontend; unit test con fake, integrazione PostgreSQL per atomicità/concorrenza e scenari HTTP/offline mirati.

## Motivazione
Una web app con backend unico può usare sessioni senza introdurre un ecosistema di token distribuiti o un account esterno. Adapter tipizzati e convenzioni test note limitano infrastruttura aggiuntiva.

## Conseguenze
Primo login online; sessione scaduta non scarta coda locale. Nessun ruolo conferito dal client. Provisioning account, recupero password e durata sessioni da specificare prima del login reale; primi test con principal e repository fake.
Versioni compatibili fissate al bootstrap, senza combinare esempi di release diverse. Memory store non utilizzato come soluzione persistente.
